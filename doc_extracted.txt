                                                
SafeDrive.mw
                        
Mobile Application System Documentation
Introduction
SafeDrive.mw is
 a proposed mobile application designed to simplify the driving licence application and renewal process in Malawi. The system is 
intended to support both first-time applicants and existing drivers while reducing unnecessary visits to Road Traffic Directorate (RTD) offices, delays and uncertainty about application progress.
 
Purpose of the System
The main purpose of SafeDrive.mw is
 to provide a convenient digital platform through which users can apply for a driving licence, renew an existing licence, submit required documents, track application progress and receive important notifications.
For new applicants, the system also provide
s access to registered driving schools. Applicants who do not already have a driving school can view schools, compare their prices and locations, and submit a request to a preferred school.
 Objectives
Simplify the driving licen
s
e application and renewal
 process.
Reduce unnecessary physical visits to RTD offices.
Allow applicants to submit and correct documents electronically.
Provide applicants with real-time or timely application-status updates.
Notify users when action is required or when their applica
tion status changes.
Help first-time applicants find and compare registered driving schools.
Provide RTD officers with a central platform for reviewing and managing applications.
Improve the overall transparency, convenience and efficiency of the process.

New Applicant Workflow
User opens SafeDrive.mw and selects 'New Applicant'.
User creates an account and logs in.
User selects the type/category of driving licence they want to apply for
.
The system displays the relevant requirements and required documents.
The user is asked whether they already have a driving school.
If the user does not have one, they can view registered driving schools and compare prices, locations and availab
le licence categories.
The user selects a preferred driving school and submits a request/application to the school.
The applicant completes the driving licence application and uploads required documents.
The system checks the application for missi
ng or incomplete information.
If something is missing, the applicant receives a notification and can correct and resubmit the information.
When complete, the application is sent to the RTD officer portal for review.
The applicant tracks the app
lication through the available status stages.
After approval, the applicant receives a notification and can access available digital confirmation/licen
s
e information and collect the physical licen
s
e where required.

Non-Functional Requirements
Non-functional requirements describe how well the system should operate.
Security: 
The system shall protect personal information, uploaded documents and account credentials from 
unauthorized
 access.
 Usa
bility: 
The application should be simple, clear and easy to navigate for users with different levels of digital literacy.
Performance: 
The application should respond promptly to common actions such as login, navigation, document upload and status ch
ecking.
 Reliability: 
The system should operate consistently and minimise failures or loss of submitted information.
Scalability: 
The system should support growth in applicants, RTD officers, driving schools, applications and stored documents.
 Compatibility: 
The mobile application should support the intended range of mobile devices and screen sizes.
 Maintainability: 
The system should be structured so that developers can fix defects, update requirements and add features without 
redesigning the entire system.
Availability: 
The service should be available to users whenever required, apart from planned maintenance or service/network outages.
Data Integrity: 
The system should maintain accurate application records and 
prevent accidental alteration or loss of data.
